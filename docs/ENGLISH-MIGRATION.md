# English-only migration

This is the implementation ledger for the repository-wide language migration.
The approved target is an English-only maintained source tree, with a bounded
transition release/tool for historical upgrades. Compatibility aliases are not
permanent features.

### Repository scope

This checkout is the only repository being developed and built. No second
checkout is required to continue the migration. The terminal plugin includes
its own Python backend and can optionally use an installed native executable.
References to that executable describe an external integration, not another
project the user must supply. Keep its existing wire format compatible while
migrating repository-owned implementation and interfaces. Record external
protocol vocabulary explicitly rather than treating it as a blocker for all
remaining work or claiming that those names have already been removed.

## Completion policy

- English names and prose for all first-party files, declarations, comments,
  documentation, UI, diagnostics, help, generated configuration and examples.
- English owned IPC/CLI vocabulary, environment variables, manifest values,
  JSON schemas, persisted paths, and symbolic states.
- Preserve external/user data, protocol bytes, copyright attribution and real
  source identities. International-input support is not language debt.
- Introduce historical readers before changing durable writers; migrate
  atomically and idempotently. Valid canonical state wins over legacy state.
- Archive migration maps and historical fixtures with the transition release;
  remove old aliases from the final runtime and current documentation.
- Preserve optional native-terminal compatibility at this repository's
  integration boundary. Do not disguise old tokens using escapes or
  reconstructed strings to claim an English-only result.
- Public contract changes include their documentation and checkers in the same
  batch. The host continues to invoke declared plugin methods.

## Verification

Run relevant checkers and regressions after each coherent change. Commands
below use the current checkout filenames:

```sh
git diff --check
python3 tools/api.py
python3 tools/docs_check.py
python3 tools/plugins.py
python3 tools/layouts.py
python3 tools/glyphs.py
python3 tools/test_text.py
python3 tools/test_plugins.py
python3 tools/test_docs.py
python3 tools/test_shortcuts.py
nix build .#k4
nix flake check
```

The package copies the source tree; its successful build is not proof that
every QML component loads. Require the affected Python/QML suites and runtime
checks. Use isolated HOME/XDG state for fixtures. Record missing dependencies
and skipped coverage explicitly. New files must be staged before flake builds.

Runtime coverage includes plugin lifecycle, native health, Settings search and
persistence, contributions, package/agent results, clipboard, OpenWebUI,
telemetry, tray, audio/network controls, authentication rehearsal, wallpaper,
terminal/SSH, notification overlap, placement and multi-monitor focus. Derive
expected membership from current catalogs instead of historical plugin counts.

Image verification requires manual review or enabled image-analysis tooling.
Never claim visual verification based on source review or build success.
